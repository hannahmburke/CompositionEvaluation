# Finance Broker Composition

This directory contains a finance-broker loan application composition used to evaluate the compliance certification method on a realistic service compositions. It includes the BPMN visualisation of the model, and the files to the implementation during evaluation. It also includes the resulting certificates for each service. 

## Scenario

A client applies for a loan through a broker. The workflow verifies the client's identity, obtains a credit score, and requests quotes from CBA, NAB, and ANZ in parallel. The broker evaluates eligible quotes, recommends a bank, and proceeds only if the client accepts the recommendation and signs the loan documents. When no eligible quote is available or the client rejects the recommendation, the loan amount can be reduced and the process retried. The workflow includes both external provider services and broker-internal activities.

## Compliance obligations

The composition is checked against these global obligations:

1. **Adult borrowers:** a completed loan must be for a client aged 18 or older.
2. **Accepted and signed loan:** before a loan is complete, the quote must have a valid interest rate, the client must have accepted the recommendation, and the documents must be signed.
3. **Low-credit-score rate buffer:** when an interest rate is selected, the obligation requires either a credit score above the threshold (50) or an interest rate above the configured minimum buffer (4.8%).

## Evaluation method

Both the composition-level and service models include exclusive choices, parallel behaviour, and retry loops.

At the composition-level, the three bank quote requests run in parallel. For parallel services in a composition, each certificate must also specify which variables its service reads and writes, and which obligation conditions it may change. 
Parallel certificates that write the same variable, read a variable written by another parallel service, or change conditions in the same obligation cannot be sufficiently verified independently in parallel. 
The composition-level verification must therefore check for these overlaps. If the parallel certificates are compatible, they can be propagated in one order rather than checking every possible ordering. 
This check is orthogonal to the contribution evaluated in this paper and can be adapted from e.g. [1]. Therefore the current implementation assumes the parallel certificates are independant (which is the case in this experiment). 
As such, the parallel components of the composition can be linearised.

Before applying this method to the fully transparent approach, we substituted each transition in the composition model with its corresponding service, to make an expanded model. Noting that the parallel components of the composition model (the bank quote requests) were linearised for a fair comparison.

We applied this model to both the fully transparent and certificate-based method. 
Each method was run five times on the model. The average was calculated after removing the maximum and minimum evaluation times.

## Results

The fully transparent method takes an average of **454s** on the expanded model. 

With the black-box method, certificate generation takes an average of **4.7s** and propagation takes **632s**, for an overall compliance-checking average of **637s**.

Unlike the artificial SAP R/3 experiments, where activities and service boundaries are random, the services in this scenario are relatively self-contained in how they affect the obligations. This creates little branching in the service-level analysis tree, and therefore the certificate generation step is fast. 
Propagation then operates on a much smaller composition model. 
However, complex output updates, particularly due to the `Make_Loan_Recommendation` service, slow propagation.
